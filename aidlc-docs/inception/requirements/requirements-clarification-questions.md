# 요구사항 명확화 질문 (Clarification Questions)

답변 분석 결과 2가지 확인이 필요합니다. Q1=C(업로드 먼저 → 영상 라이브러리) 선택은 Q2=A(양쪽 모두 선택 가능), Q3=A(새 레코드+S3 복사), Q4=A(통합 대체)와 **정합적**입니다 — 라이브러리 방식에서는 모든 처리가 "업로드된 영상 선택"에서 시작하므로 자연스러운 조합입니다. 다만 아래 2가지가 모호합니다.

## Ambiguity 1: 메타데이터 수집 시점
원래 요청문에는 "업로드 화면은 … 쇼츠만들기에서도 최초 업로드시 필요한 항목도 참고하여 받기"라고 되어 있으나, Q1=C(라이브러리 방식)에서는 업로드 시점에 파이프라인이 정해지지 않으므로 쇼츠용 항목(모델·클립 수·테마·길이)이나 화자별 항목(발표자 수·이름)을 업로드 시점에 받을 필요가 없습니다.

### Clarification Question 1
쇼츠/화자별 메타데이터는 언제 입력받을까요?

A) **처리 시점에 입력** (권장): `/upload`는 영상 파일만 업로드(제목 정도만 입력). 쇼츠만들기/화자별 편집 메뉴에서 영상을 선택하면 그때 해당 목적의 폼(쇼츠: 모델·클립수·테마·길이 / 화자별: 모델·발표자 수·이름)이 나타나고, 입력 완료 시 처리 시작 — 원래 요청문의 "필요한 항목 받기"가 처리 시점으로 이동

B) **업로드 시점에 모두 입력**: `/upload`에서 두 목적의 항목을 모두 입력받아 저장해 두고, 이후 메뉴에서 영상 선택 시 저장된 값으로 즉시 처리 (불필요한 항목까지 입력해야 하고, 라이브러리 방식의 장점이 줄어듦)

X) Other (please describe after [Answer]: tag below)

[Answer]: A

## Ambiguity 2: 기존(레거시) 영상 포함 여부
이 변경 이전에 기존 흐름으로 업로드된 영상들은 `videos/{historyId}/RAW.mp4` / `videos/{editId}/LONG_RAW.mp4` 키에 있습니다. 새 라이브러리(별도 키 구조)와 위치가 다릅니다.

### Clarification Question 2
쇼츠만들기/화자별 편집의 "영상 선택" 목록에 레거시 영상도 포함할까요?

A) **새 라이브러리 영상만** (권장): 이 변경 이후 `/upload`로 올린 영상만 선택 가능. 레거시 처리 이력은 기존 History 화면에서 그대로 확인 (참고: 현재 프로덕션 스토리지 버킷은 최근 재생성되어 레거시 영상 파일이 없는 상태라 실익 차이 없음)

B) **레거시 포함**: 기존 History/LongVideoEdit 레코드의 원본 영상도 목록에 표시하고 선택 시 복사·재처리 (레코드-파일 존재 여부 대사 로직 추가 필요)

X) Other (please describe after [Answer]: tag below)

[Answer]: B
